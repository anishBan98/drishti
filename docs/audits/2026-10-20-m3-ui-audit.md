# M3 UI and UX audit (20 Oct 2026)

Hands-on test of the running app (home page and the eight `/demo` screens) on desktop (1440 × 900, 1280 × 720, 1024 × 768, 1920 × 1080), tablet (731 × 742), phones (390 × 844, 320 × 568) and a sideways phone (844 × 390), in both themes. Happy paths were clicked through by hand. Unhappy paths were forced with a script: data that fails to load or has the wrong shape, unknown links, blocked browser storage, double clicks, reload mid-action, bad dates, keyboard-only use and 200 % text.

Every finding marked **Fixed** has a regression test in `e2e/tests/audit.demo.spec.ts`.

## Needs a decision

- **The same ₹30 L budget move is suggested while an identical one waits for approval.** This week suggests "Move ₹30 L to stronger channels" while the Actions log already has "Shift ₹30 L to quick commerce and creators" waiting for approval. Together they double-count the money in "Expected impact". The docs do not say what should happen. Proposed rule for docs/08 §9: *a suggestion is not shown while an action of the same type for the same target is waiting, running or measuring; the card links to that action instead.* This needs the engine to read open actions. I suggest doing it in M6, where the measurement work touches the same code.
- **Spec gaps that the demo cannot reach yet:** skeleton loaders (docs/09 §7) and a Retry button on failed action cards (docs/09 §5.1). The demo never fails an action, and loading takes well under a second. Planned for M4, when real data and the API arrive.

## Checked and working

- Home: theme toggle, Open the demo, sample-sheet download, setup and guide links, the game end to end (right and wrong answers, XP, streak, badges, score card, best score kept in the browser, Play again), every size listed above with no page scroll.
- Demo: every nav link; light and dark on every screen; the period, channel and product menus (each explains the demo has one option); the workspace menu; run, cancel, approve, decline, undo, assign and "I've done it"; output downloads; double-clicking Run creates one action; with browser storage blocked the screens load and the theme still switches (the game was not checked that way); 200 % text does not clip.
- Accessibility (axe, WCAG 2.2 AA) and the visual comparison with the designs still pass after the fixes.
